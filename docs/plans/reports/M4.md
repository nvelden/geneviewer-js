# M4 reports

Branches: `m4-record-spec` in the R repo, `m4-compile` in geneviewer-js.
Summary for the milestone review at the end.

## Decisions taken during M4 (Niels, 2026-11-04)

Asked in M4.1, because the plan's rule "the spec holds the results of data
processing" does not fit two R functions:

1. **`GC_align`** sets each cluster's scale start and end from that
   cluster's scale breaks and direction, and R does it again after every
   `GC_scale()`. Automatic breaks are worked out by compile(), so R cannot
   give the result in advance. Decided: a spec key
   `align: { idColumn, id, align }`, resolved by compile(). This replaces
   NAMING.md point C for `GC_align`.
2. **`GC_links(group, value1, value2)`**: besides matching genes, the
   renderer uses them to choose the genes that get the measure as a label.
   Decided: keep them in the spec as `links.group`, `links.value1` and
   `links.value2`, next to `links.data`.

Both are NAMING.md cases 22 and 23; their names are for Niels to review.

## M4.1: R records the spec (R repo)

**Commit:** ec244fa on m4-record-spec (R repo), after 14de4de on main.

**Done:**
- `R/spec.R` (new): `spec_args()` takes the arguments given in a call
  (`match.call()`, values forced at the top of the function), without the
  chart, NULLs and empty lists. `add_spec()` adds them under the spec key
  with the spec names: `cluster` → `clusters`, snake_case → camelCase, and
  the renames NAMING.md decided (`show_links` → `show`,
  `legendOptions` → `markerStyle`, `sequenceStyle` → `lineStyle`, ...).
  - One call gives an entry; more calls, or calls with `cluster =`, give an
    array of entries in call order.
  - Chart-wide components follow R: `title`, `legend` and `toolbar` merge;
    `color`, `pattern`, `events` and `align` replace; `zoom` merges and a
    new mode drops the old range and minimum; `theme` starts again when a
    theme is given and otherwise merges as `merge_theme_settings()`.
  - `annotation` and `elementStyle` are always arrays.
    `GC_element_style(reset = TRUE)` removes the earlier entries of that
    element instead of adding one.
  - A logical given for a column argument (`GC_labels(FALSE)`,
    `GC_legend(FALSE)`, `GC_tooltip(FALSE)`, ...) is recorded as `show`.
  - `GC_chart`: `version`, the data as given (or as read from GenBank
    files, with `fields.cluster` and `fields.strand` set as R sets them),
    `fields`, `width`, `height`, `style`. `save_button = FALSE` is
    `toolbar.buttons` without "save", as NAMING.md decided.
  - Data processing writes data: `GC_links(group = )` records the table
    `get_links()` made in `links.data` (and drops `group` when `data` was
    given); `GC_transcript()` replaces `spec$data` with the data and its
    introns; `GC_normalize()` replaces `spec$data` with the shifted data,
    also in the columns named as start and end.
  - Theme options of components are recorded under their JavaScript names
    (`corner_radius` → `cornerRadius`), as R sends them.
- Each `GC_*` function: `spec <- spec_args(...)` first, `add_spec(...)` at
  the end. Calls that R ignores (`GC_title(show = FALSE)`,
  `GC_labels(show = FALSE)`, a warning that returns the chart unchanged)
  are not recorded.
- `GC_transcript()` keeps the spec when it makes the chart again
  (`keep_chart_settings()` calls `GC_grid()`, which would record a grid).
- `GC_chart()` leaves `spec` out of `x$params`; `render_theme()` takes the
  spec out before resolving palette names, so it stays as recorded.
- `tests/testthat/test-spec.R`: the spec is NULL without the option; the
  payload with the option, spec removed, equals the payload without it; the
  recorded entries, names, merges, resets, flags, links, transcripts and
  normalised data; schema validation with `jsonvalidate` (skipped when it
  is missing, or when `GENEVIEWER_SPEC_SCHEMA` does not point to
  `spec-v1.schema.json`). `jsonvalidate` is added to Suggests.
