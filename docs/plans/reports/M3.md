## M3.3: Schema draft

**Commit:** c176da3 on m3-modules-schema

**Done:**
- `schema/spec-v1.schema.json`, JSON Schema 2020-12. Top level: `version`
  (const 1), `data` (rows or columns), `fields`, `width`, `height`,
  `style`, `saveButton`, and one key per `GC_*` chart function (25).
  - Components with `cluster =` take one entry or an array of entries. Each
    entry may have `clusters`: names or 1-based positions.
  - `annotation` and `elementStyle` are arrays of items. `theme` is a
    theme's name or an object.
  - Shared types are in `$defs`: `style`, `itemStyle`, `groupStyle`,
    `colors`, `clusterRef`, `scaleBreak`, `data`, and others.
  - `default` is R's default where R has a value. Where R's default is
    `NULL`, the description says what applies (the theme's value,
    otherwise ...).
  - Components whose R function takes `...` allow other properties: the
    JavaScript options R passes through.
- `schema/NAMING.md`: every R argument and its spec name (259 rows).
  - 21 marked cases, each with a proposal.
  - Three general points: A, plurals; B, options passed through `...`;
    C, data processing is not in the spec.
- `schema/examples/basic.json`: an example spec, checked against the
  schema.
- `scripts/schema-check.mjs` (`npm run schema:check`, in CI). It checks
  that:
  - the schema is valid 2020-12 and compiles with ajv;
  - every argument in `test/coverage.md` has a row in NAMING.md;
  - every spec name in NAMING.md resolves to a property of the schema;
  - the examples validate.
- `ajv` 8.20.0 as a devDependency, pinned exactly. README: schema section.

**How it was made:** a script read the formals of the 29 exported `GC_*`
functions and their Rd argument text from the R package (`pkgload`,
`tools::Rd_db`). The schema and NAMING.md were generated together from
one table, so they agree. Descriptions are shortened from the Rd text.

**Checks run:**
- `npm run schema:check`: all passed (286 R arguments, 259 rows).
- I checked that it fails when it should:
  - a row removed from NAMING.md: "no row for GC_tooltip:formatter";
  - a misspelled spec name: "links.curvy is not in the schema";
  - an invalid example: wrong type and an unknown key.

**Deviations from the plan:**
- Not in the spec, with the reason in NAMING.md:
  - `GC_align`, `GC_normalize`, and `GC_links(group, value1, value2)`:
    data processing, which stays in R and Python;
  - `GC_zoom_to`: a Shiny command;
  - `GC_chart(elementId)`: the element is `newChart`'s argument;
  - `GC_element_style(reset)`: marked, case 8.
- The `...` options are allowed but not listed (point B).

**Found along the way:** none.

**Questions (Niels):** the 21 marked cases and points A–C in
`schema/NAMING.md`. M3.4 (types) waits for them, since `spec.d.ts` is
