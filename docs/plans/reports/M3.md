## M3.1: esbuild, no code changes

**Commit:** bf62afd on m3-modules-schema

**Done:**
- `package.json`: `esbuild` 0.28.2 as a devDependency, pinned exactly.
- `scripts/bundle.mjs`: the esbuild settings (IIFE, not minified, `d3` read
  from the page's global). `geneviewer.js` and `chart.js` are still
  classic scripts, so a small plugin joins them, unchanged, into one module
  `geneviewer:scripts`. This plugin goes in M3.2.
- `src/index.js`: the entry. It exports `newChart` and `version`, and
  `chartToSVG` and `chartToPNG` (see below).
- `scripts/build.mjs`, `files.mjs`, `check.mjs`: `dist/geneviewer.js` is
  the esbuild bundle; the other dist files are copied as before.
- **Old globals (decided by Niels during this step).** Before, every
  top-level function of `geneviewer.js` was a page global. Some tests
  outside this repo call them:
  - the app's `tests/browser/chart-wide-drag.cjs` calls `chartToSVG(el)`;
  - the R package's `test-color-bar.R` and `test-zoom.R` call
    `chartToSVG(el)`, and `test-png-export.R` calls `chartToPNG(el)`;
  - `test-render-events.R` replaces `window.makeLinks` to simulate a failed
    draw.

  Niels chose aliases in the R binding:
  - `geneviewer.chartToSVG` and `geneviewer.chartToPNG` are exported.
  - `src/htmlwidgets/geneviewerwidget.js` sets `window.chartToSVG` and
    `window.chartToPNG` to them until M6.
  - The `makeLinks` test cannot work on a bundle. M6 rewrites it.
- **Tests:**
  - `test/warnings.cjs` called `getColorScale` as a global. It now uses a
    test-only bundle: `scripts/build-test.mjs` builds
    `test/harness/internals.js` into `test/harness/build/internals.js`
    (ignored by git) as the global `geneviewerInternals`, and the test adds
    it to its page.
  - `scripts/test-docker.sh` builds it before the tests.
- Workflows (`ci`, `test`, `release`, `pages`): `npm ci` before building,
  since the build now needs esbuild.
- README: build section.

**Checks run:**
- `grep` of the binding: it uses only `geneviewer.newChart` (and now
  `geneviewer.chartToSVG`/`chartToPNG` for the aliases).
- `npm run check`: ok.
- `npm test`: 412 passed, 0 failed; interaction, save, two charts, site,
  warnings: all passed.
- `npm run try-app -- --r-tests`:
  - app testthat: passed;
  - browser tests: 12 passed, 0 failed. Before the aliases,
    `chart-wide-drag.cjs` failed on `chartToSVG is not defined`.
  - R package: `[ FAIL 4 | WARN 3 | SKIP 6 | PASS 1660 ]`. All 4 failures
    are in one test, `test-render-events.R` "render events follow
    successful drawing...", which replaces `window.makeLinks`.

**Deviations from the plan:**
- The entry joins the two scripts with a plugin. They cannot be imported
  separately: `chart.js` uses `geneviewer.js`'s functions as globals.
- The `chartToSVG`/`chartToPNG` exports and aliases (above).

**Found along the way:**
- esbuild drops comments, apart from licence comments. The bundle is
  readable and not minified, but it has no comments. CRAN asks for
  readable source, which this still is. The commented source is in this
  repo.
- esbuild warns about two duplicate keys in one object literal in
  `geneviewer.js` (`strokeWidth`, `cursor`). The later key wins, as before.
  M3.2 removes the dead first key, since its check needs zero warnings.
- For M6: `test-render-events.R` must stop replacing `window.makeLinks`.
  The R and app tests should use the chart's `toSVG`/`toPNG`, so the
  aliases can go.

**Questions:** none.

## M3.2: Split into modules

**Commit:** see the M3.3 report (the hash is written by the next step) on
m3-modules-schema

**Done:**
- `src/geneviewer.js` and `src/chart.js` are now 25 modules in `src/lib/`.
  Each top-level statement moved with the comments above it. A script
  generated each module's `import` and `export` lines from the names its
  code uses, found by a scope analysis, not by text search.
  - `util.js`, `style.js`, `text.js`, `color.js`, `scale.js`,
    `container.js` (the `container` class, `createContainer`, and the
    `cluster` and `geneData` methods), `export.js`, `links.js`;
  - `components/*.js`: one per drawn part, 16 files: scale, title, footer,
    clusterLabel, sequence, coordinates, scaleBar, labels, tooltip, genes,
    transcript, legend, links, trackMouse, zoom, annotations;
  - `chart.js`: `newChart`, without its wrapping function. It exports
    `newChart` and `version` and no longer sets `window.geneviewer`.
  - `index.js`: imports the components and exports `newChart`, `version`,
    `chartToSVG` and `chartToPNG`.
- Edits besides `import`/`export`:
  - a one-line header comment per module;
  - four stale section headings removed ("// Utils", "// Make links
    function", "// Cluster functions", "// Annotations");
  - the `themeOptionsKey` comment moved back to the `title` method;
  - the duplicate keys esbuild warned about, in the transcript's intron
    and UTR defaults. `strokeWidth: 0, ..., strokeWidth: 1` became
    `strokeWidth: 1` in the first key's place, and the second `cursor:
    "default"` was removed. Values and key order are as JavaScript gave
    them before.
- `scripts/bundle.mjs`: the join plugin is gone. Any esbuild warning now
  fails the build.
- `scripts/check.mjs`: checks every module in `src/lib/` and reads the
  version from `src/lib/chart.js`.
- `test/harness/internals.js` imports `getColorScale` from
  `src/lib/color.js`.
- README: contents table and the release steps' version file.

**Checks run:**
- `npm run build`: no esbuild warnings.
- Scope analysis of every module (acorn and eslint-scope): no names used
  apart from the module's own, its imports and browser globals (`d3`,
  `window`, `document`, ...); no unused imports.
- The module lines against `main`'s two files, as a multiset, with
  imports, headers and `export` keywords set aside: the only differences
  are the edits listed above.
- `npm run check`: ok.
- `npm test`: 412 passed, 0 failed; interaction, save, two charts, site,
  warnings: all passed.
- `npm run try-app -- --r-tests`:
  - app testthat: passed; browser tests: 12 passed, 0 failed;
  - R package: `[ FAIL 4 | WARN 6 | SKIP 9 | PASS 1627 ]`. The 4 failures
    are the same `makeLinks` test as in M3.1. The skips, 3 more than in
    M3.1, are R browser tests with "Chrome could not be started"
    (chromote), so fewer tests passed. Different tests were skipped in the
    M3.1 run for the same reason.
- `dist/geneviewer.js`: 5,152 lines, not minified.

**Deviations from the plan:**
- `wrap` is in `text.js`, not `util.js`: it uses `styledSegments` from
  `text.js`.
- `styleFontText` and `titleAlignment` are in `components/title.js`,
  which `components/footer.js` imports.
- The cluster title is drawn by `container.prototype.title`, so there is
  no separate cluster-title module.

**Found along the way:**
- chromote in the R tests often fails to start Chrome on this machine. The
  tests are then skipped, not failed, so the counts vary from run to run.

**Questions:** none.
