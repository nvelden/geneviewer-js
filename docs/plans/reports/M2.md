## M2.3: Move the chart out of the factory

**Commit:** 57e295c on m2-core

**Done:**
- `src/chart.js`: the body of `factory` as `newChart(el, renderModel,
  options)`, which draws at once and gives the chart: `update`, `resize`,
  `on` (gives the function that removes the handler), `off`, `zoomTo`,
  `toSVG`, `toPNG`, `destroy`. JSDoc on `newChart` and the chart's
  methods. `window.geneviewer = { newChart, version }` at the end. The code
  is otherwise as it was, apart from:
  - `report(name, detail)` calls the `chart.on` handlers, then dispatches
    the DOM event. `geneviewer:dragmove` goes through it too.
  - The Shiny zoom handler and the `zoomTargets` map are now `zoomTo`; the
    map and the message handler move to the binding in M2.4.
  - Module-level, shared: `renderSequence`, `activeShortcuts` with its one
    keydown listener, the history and layout helpers. Per chart: all
    selection, drag, history, zoom and handler state.
  - A chart on an element without an id gets its own id for its parts'
    ids (`geneviewer-chart-<n>`), so two such charts do not collide. `el`
    is not changed.
- **Options:**
  - `saveAs(blob, filename)`: given to the save menu (M2.2).
  - `on: { name: handler }`: handlers added before the first draw. Without
    it, `chart.on()` can only be called after the first draw and misses its
    `rendered` and `zoom` events. The binding needs them for the first
    `_rendered` and `_zoom` inputs.
  - `server` (default false). Three things happened only in Shiny mode, and
    `chart.js` must not know about Shiny. With `server: true`, a fixed pixel
    width in `size` is applied to `el`, clicks are reported, and moves
    wait for the server's redraw instead of being kept in the chart. The
    binding sets it in Shiny mode (M2.4).
- `scripts/files.mjs`, `build.mjs`: a dist file can be made of several
  source files. `dist/geneviewer.js` is `geneviewer.js` + `chart.js`; the
  set of dist files is unchanged.
- `scripts/check.mjs`: checks `chart.js`, and that its `version` equals
  `package.json`.
- Harness: `mount.js` has two modes, `binding` (the R binding, as before)
  and `direct` (`geneviewer.newChart`), chosen by `?mode=`. In direct mode
  the interaction tests record events through `options.on`, in binding mode
  as DOM events, against the same baselines. `run.cjs` and
  `interaction.cjs` run both modes (`--mode` picks one; `--update` writes
  from binding mode); `save.cjs` runs both.
- `test/two-charts.cjs` (the plan's pitfall): two charts from
  `vig-geneviewer-5` on one page. Selecting and dragging in one reports
  only to its handlers. Ctrl+Z after a click in the other undoes nothing.
  Ctrl+Z in the first undoes its drag. After `destroy()` the other still
  works.
- README: the tests section lists the modes and the new tests.

**Checks run:**
- `npm run check`: ok, version 0.2.0.
- `npm test`: 412 passed, 0 failed (206 fixtures, both modes);
  interaction: all passed (both modes); save: all passed (both modes);
  two charts: all passed (10 checks).
- `grep -nE "HTMLWidgets|Shiny|saveAs\(" src/geneviewer.js src/chart.js`:
  nothing.
- `this` in `mergeOptions`: every call in `chart.js` passes the theme
  itself, and `chart.js` is not strict code, so nothing changed.

**Deviations from the plan:**
- Added `options.on` and `options.server` (above).
- Click events are only reported with `server: true`, as before only in
  Shiny. In Shiny they now also come as a `geneviewer:click` DOM event,
  which they did not before.

**Found along the way:** none.

**Questions:**
- Should a chart without a server report clicks when `GC_events(click =
  TRUE)`? For a JavaScript user, `chart.on("click")` only works with
  `server: true` today. Changing it changes standalone R output: the chart
  gets the hover highlight (`geneviewer-highlight`) with `GC_events(click =
  TRUE, highlight = TRUE)`. If yes, I would propose it as a row on the
  exceptions list for M3 or M4.
