Install

With a script tag, which defines a global geneviewer:

<script src="https://cdn.jsdelivr.net/npm/geneviewer/dist/geneviewer.min.js"></script>

Or from npm, for use with a bundler such as Vite or webpack:

npm install geneviewer
import { newChart } from "geneviewer";

D3 is included in the script-tag build. The npm build imports d3 as a dependency, so a project that already uses D3 loads it once.

Quick start

<div id="chart"></div>
<script>
  const genes = [
    { cluster: "ophA", name: "ophB1", start: 2522, end: 4276, class: "Monooxygenase" },
    { cluster: "ophA", name: "ophC",  start: 5286, end: 4718, class: "NTF2-like" },
    { cluster: "ophA", name: "ophA",  start: 9536, end: 10904, class: "Methyltransferase" },
  ];

  const chart = geneviewer.newChart("#chart", {
    data: genes,
    fields: { cluster: "cluster", start: "start", end: "end", group: "class" },
    height: "160px",
    labels: { label: "name" },
    legend: { group: "class" },
  });

  chart.on("select", (event) => console.log(event.detail));
</script>

A gene whose start is greater than its end is drawn on the reverse strand, unless a strand field says otherwise.

The chart spec

A chart is described by one plain object, which can be written as JSON. Its keys mirror the R package's functions: GC_labels() becomes labels, and arguments become camelCase fields, so R users will recognise every part. 

{
  version: 1,
  data: genes,
  fields: { cluster: "cluster", start: "start", end: "end", group: "class", strand: "strand" },
  width: "100%",
  height: "400px",
  theme: "dark",

  title: { title: "OphA gene clusters", subtitle: "Omphalotus olearius" },
  labels: { label: "name" },
  legend: { group: "class", position: "top" },
  colors: { Monooxygenase: "#1f77b4" },
  links: { data: homologs, measure: "identity" },
  zoom: { show: true },
  events: { select: true },
}

Data and fields

data is the gene table, in either shape:

  • Rows: an array of objects, one per gene.
  • Columns: an object of equal-length arrays, such as { start: [...], end: [...] }. This is smaller and is what the R and Python packages send.

fields says which columns hold what:

FieldRequiredDescription
start, endyesGene positions. Default column names start and end.
clusternoWhich cluster each gene belongs to. Without it, all genes are one cluster.
groupnoColours genes and fills the legend.
strandnoForward: 1, forward, sense or +. Reverse: -1, 0, reverse, antisense, complement or -. Without it, the strand follows from start and end.

Any other columns can be used in labels, tooltips and links.

Per-cluster settings

Any component can also be an array. Entries apply in order; an entry with clusters applies only to those clusters, by name or by 1-based position: 

labels: [
  { label: "name" },                      // every cluster
  { clusters: ["dbophA"], show: false },  // then hide labels in dbophA
]

Events

Handlers get an object whose detail describes what happened. These are the events the R package already reports to Shiny; today they are also sent as DOM events named geneviewer:<name>, which you can see in the interactive example.

EventWhen
clickAn element was clicked (needs events: { click: true }).
dblclickAn element was double-clicked.
selectThe selected element changed.
selectionThe list of selected elements changed.
dragOne element was moved.
movesSeveral elements were moved at once, or a move was undone or redone.
zoomThe zoom window changed.
renderedThe chart finished drawing.

Styles are added to the page with the first chart, so there is no CSS file to load. geneviewer.css is included for pages whose Content-Security-Policy does not allow that.

Versions

  • Library: semantic versioning from 1.0. While on 0.x, minor versions may change the API.
  • Spec: the version key, starting at 1. A chart with a newer major spec version than the library knows is drawn as far as possible, with a warning in the console.
  • Schema: the spec is defined by a JSON Schema in the repository. The TypeScript types, this reference and the Python package's input checks are generated from it.

R and Python

The R and Python packages build a spec and call newChart, so a chart looks and behaves the same in R, Python and JavaScript. They keep all loading and processing of data: reading GenBank, GFF, FASTA and BED files, protein alignment and MUMmer, matching genes for links, deriving introns, and aligning or normalising cluster positions. The results are gene and link tables that go into the spec; the library only draws them.
